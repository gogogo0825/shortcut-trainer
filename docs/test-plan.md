# テスト計画

- Unit（Vitest）: キー正規化、複数段階判定、タイムアウト、IME、採点、XP、習熟度、復習日、CSV/JSON/Zod検証。
- Integration: IndexedDB永続化・移行・バックアップ・問題ID維持・分析集計。
- E2E（Playwright）: ガイド/クイズ/4択、履歴、インポート、設定、モバイル表示、公開サブパス。
- Accessibility: 自動axeチェック、キーボードのみの操作、フォーカス、読み上げ、色・コントラスト、縮小動作。
- 手動実機: Windows JIS、Edge/Chrome、ブラウザ予約キー、複数段階入力、IME、画面離脱。
- 問題品質: 出典URLの実在、対応製品・バージョン、操作結果、検証者と日付、重複、曖昧な表現。

## 自動検証コマンド

`npm test`、`npm run e2e`、`npm run e2e:pages`、`npm run typecheck`、`npm run build`、`npm run lint`、`npm audit`、`npm run validate:questions -- --details`。`e2e:pages` は本番ビルドを作り、ローカルのサブパスでアセット、HashRouterの再読込、4択、IndexedDB、バックアップ復元を検証します。実際のPages・ブラウザー実機は検証しません。

## 公開前の実機チェック（未実施）

実施日時、確認者、Windows・ブラウザー・対象アプリのバージョン、結果と問題を記録する。個人の既存データを使わずテスト用プロファイルを使用する。

- [ ] Windows JISでEdge最新版とChrome最新版それぞれを確認。Ctrl/Shift/Alt、左右キー、複数段階、IME、誤入力・再挑戦・タイムアウトを試す。
- [ ] OS/ブラウザー予約キーで直接入力できない場合、4択・自己申告へ切り替えて記録が区別されることを確認する。
- [ ] PCでガイド、クイズ、出題順、分析、復習、設定、XPを試す。再読込後の履歴を確認する。
- [ ] スマートフォン・タブレットの実機で4択、分析、復習、横スクロールと操作性を確認する。
- [ ] [アクセシビリティチェックリスト](./accessibility-checklist.md)の読み上げ、コントラスト、拡大、キーボード操作、動き抑制を実施する。
- [ ] [問題状況](./question-status.md)を見て公式資料・対象バージョンと実機操作を確認し、確認者・日付を記録する。
- [ ] 公開承認後、Pagesの実URLでルート、アセット、画面遷移・再読込、4択、IndexedDB保存、バックアップ出力・復元を確認する。
