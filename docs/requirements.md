# Shortcut Trainer 要件定義書 v1.0

## 1. 目的と対象
Windowsで使うショートカットを効率よく習得するブラウザアプリ。PCでは物理キーボードで練習し、スマホ・タブレットでは4択、復習、学習分析を利用する。初期リリースは日本語UI。バックエンド・ログイン・自動同期は不要。

## 2. 確定した30項目
1. Webアプリ。
2. ガイド練習（操作とキーを表示、正解まで再試行）とクイズ（操作のみ表示、初回入力を採点）。
3. Windows / Excel / Word / PowerPoint / VS Code / ブラウザの6カテゴリ。
4. 難易度順・ランダム・習熟度に基づく適応型出題。
5. 正答率、回答時間、問題別習熟度、カテゴリ進捗、日次推移、弱点順位、連続学習、復習提案を記録・可視化。
6. IndexedDBでローカル保存、JSONでエクスポート・インポート。サーバーなし。
7. 標準問題＋独自問題CRUD＋CSV/JSON一括取込。
8. キーボード表示ON/OFF、正解キーのハイライト、押下状態表示、日本語配列を考慮。
9. ガイドは正解まで繰返し、クイズは初回回答を採点し進行。誤答と応答時間を記録。
10. OS/ブラウザ予約キーは直接検出・4択・自己申告を併用し、採点方法を区別して記録。
11. 5/10/20/50問、1/3/5/10分、無制限のセッション。
12. 控えめなXP、レベル、連続正解、連続学習日数。
13. ミニマルUI＋控えめな演出、ライト/ダークモード。
14. PCフル機能、スマホ/タブレットは4択・復習・分析。端末間の自動同期なし。
15. React + TypeScript + Vite。Tailwind CSS、Recharts等は適切に採用。
16. ローカル開発＋GitHub Pages公開。
17. 全体設計を先に行い、フェーズ別に実装。
18. 標準問題約180問（6カテゴリ×約30問、目安は初級10・中級12・上級8）。最初は20〜30問から。
19. 公式資料に基づき作成、形式自動チェック、必要な実機検証。出典・検証状況を追跡。
20. Vitest + Playwright + 実機確認。
21. 仕様書＋Copilot設定＋フェーズ別プロンプト。
22. Copilot Agentで可能な限り自律実装。破壊的変更、コミット、公開は人の承認を求める。
23. 画面一覧＋画面遷移図＋ワイヤーフレーム。
24. README＋ユーザーマニュアル＋開発者向け文書。
25. 重要な詳細を5問追加して設計。
26. 拡張可能なキー入力エンジン（修飾キー、複数段階、配列、タイムアウト）。
27. 正答率・速度・直近成績・間隔反復に基づく習熟度と復習予定日。
28. 標準問題はカテゴリ別JSON＋Zod等による検証＋バージョン管理。
29. WCAG 2.2 AAを目標に設計・検証（達成を自動的に保証しない）。
30. 全機能・テスト・問題検証・公開確認を完成条件とする。

## 3. 振る舞いの詳細
- 問題は操作名、説明、対応OS/アプリ、難易度、キー手順、出典、検証状態、採点方式を持つ。
- 練習中はキー入力の捕捉範囲を限定し、Tab・Escapeなどの通常の画面操作を不必要に妨げない。入力欄フォーカス中はショートカットを横取りしない。
- キー入力がブラウザに届かない問題を自動採点可能と偽らない。代替採点方式を明示する。
- 4択・自己申告は直接入力とは別の評価方法として保存し、習熟度への反映を区別できるようにする。
- タイムアウト、ページ離脱、未回答、再挑戦を記録。練習の再試行はクイズ初回正答率に混入させない。
- 回答時間は問題提示から確定入力までを単調時計で測り、タブ非表示等の中断を考慮する。
- 学習記録のJSON復元は事前プレビュー・スキーマ検証・重複処理選択・失敗時の安全なロールバックを備える。
- 標準問題の更新は安定IDを維持し、内容変更はrevisionで追跡する。削除済み問題の学習履歴は保持する。
- 独自問題IDが新しい標準問題IDと衝突した場合、独自問題・回答履歴・習熟度・セッションの参照を原子的に独自IDへ移し、標準問題と独自問題の両方を利用可能にする。復元バックアップも旧形式を受け付け、ID参照を一貫して移す。データ変更が失敗した場合は全体をロールバックする。
- revision更新後も旧revisionの回答と当時の正誤を保持する。旧revisionの回答は履歴・全体分析に表示するが、正解キーに基づく現行revisionの習熟度・復習期限には反映しない。
- 標準問題の実機検証画面でカテゴリ・難易度・実機結果を絞り込み、対象環境、検証日時、配列、備考と結果を保存する。正常動作は対象アプリで人が明示的に確認した自己申告のみとし、ブラウザーでの入力検出とは区別する。現行revisionの最新結果を進捗に使い、旧revisionの記録は保持する。実機記録は学習履歴から独立し、バックアップ・復元とJSON出力に対応する。

## 4. 非機能・制約
- データは原則端末内。個人データを外部へ送信しない。外部CDN/解析サービスは既定で不要。
- GitHub Pagesのサブパス配置、リロード時のルーティング、静的アセットパスを検証。
- Edge/ChromeのWindows最新版を優先。Firefox等は対応状況を明記して確認。
- 日本語JIS配列を優先し、US配列差異をデータで表現可能にする。
- UIのWCAG 2.2 AAを目標とし、自動検査だけで適合を宣言しない。
- 自動化が困難なOS予約キーは手動検証項目に分離する。

## 5. 未確定事項と実装時の扱い
- 習熟度の重み・忘却間隔は `docs/architecture.md` の初期案を使用し、設定可能な定数として分離する。
- 出典URLや対応バージョンは実際に公式資料を確認して記入。架空のURLを埋めない。
- 問題数の約180問は目標値。検証前の問題を「検証済み」として公開しない。
- ブラウザによるキー捕捉制約はブラウザ別に調査・実測する。
